== Platform Overview (Visual)

image::idp-architecture.svg[IDP Architecture Overview,800,align="center",link=self,window=blank]

This diagram shows all 6 layers of the platform, from the pre-installed foundation (Layer 0) to the developer portal (Layer 5). Each layer builds upon the previous, following a clear deployment progression.

== GitOps Deployment Flow

[ditaa]
----
  +------------------+
  |  Platform Team   |
  |  (Developer)     |
  +--------+---------+
           |
           | 1. Update Helm chart
           v
  +------------------+
  |   GitLab Repo    |
  |  (Helm Charts)   |
  |  branch: main    |
  +--------+---------+
           |
           | 2. ArgoCD polls repo
           |    (or webhook trigger)
           v
  +------------------+
  |  ArgoCD          |
  |  (openshift-     |
  |   gitops)        |
  +--------+---------+
           |
           | 3. Helm render + kubectl apply
           v
  +------------------+
  |  OpenShift       |
  |  Cluster         |
  |  - Operators     |
  |  - Deployments   |
  |  - Services      |
  +------------------+
           |
           | 4. Status sync back
           v
  +------------------+
  |  ArgoCD UI       |
  |  (Healthy/       |
  |   Synced)        |
  +------------------+
----

== Component Dependencies

This diagram shows the deployment order and dependencies:

[ditaa]
----
    Layer 0: Pre-installed
    +------------------------------------------------------------+
    | OpenShift Cluster | GitLab | Vault | NooBaa | Keycloak   |
    +------------------------------------------------------------+
                            |
                            v
    Layer 1: Platform GitOps
    +------------------------------------------------------------+
    | OpenShift GitOps (ArgoCD)                                  |
    | - Installed by cluster admin                               |
    +------------------------------------------------------------+
                            |
                            v
    Layer 2: CI/CD & Secrets
    +------------------------------------------------------------+
    | OpenShift Pipelines | External Secrets Operator           |
    +------------------------------------------------------------+
                            |
                            v
    Layer 3: Registry & App GitOps
    +------------------------------------------------------------+
    | Red Hat Quay | ArgoCD (rhdh-gitops)                        |
    +------------------------------------------------------------+
                            |
                            v
    Layer 4: Developer Tools
    +------------------------------------------------------------+
    | Dev Spaces | Trusted Artifact Signer                       |
    +------------------------------------------------------------+
                            |
                            v
    Layer 5: Developer Portal
    +------------------------------------------------------------+
    | Red Hat Developer Hub (integrates all above)               |
    +------------------------------------------------------------+
----

           |
           | 2. External Secrets Operator reads
           v
  +------------------+

  | - Points to Vault|
  | - Auth via SA    |
  +--------+---------+
           |
           | 3. Sync secret
           v
  +------------------+
  | ExternalSecret   |

  | - Defines        |
  |   mapping        |
  +--------+---------+
           |
           | 4. Creates K8s Secret
           v
  +------------------+
  |  Kubernetes      |

           |

           v
  +------------------+

  | Pod              |

  |  GitLab, etc.)   |
  +------------------+

  | Verify: ArgoCD, GitLab, Vault, Keycloak, NooBaa |
  +--------------------------------------------------+
                      |
                      v

  +--------------------------------------------------+
  | Deploy: Pipelines, Quay, ESO, ArgoCD (apps)     |
  +--------------------------------------------------+
                      |
                      v
  Module 3: Identity & Secrets
  +--------------------------------------------------+

  +--------------------------------------------------+
                      |
                      v

  +--------------------------------------------------+

  +--------------------------------------------------+
