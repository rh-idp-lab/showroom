*Challenge #7: "How do we know the image in production is what we actually built?"*

Golden Path Inc.'s security auditor just asked a simple question: _"Can you prove that the container running in production right now was built from that specific commit in Git?"_ Nobody could answer. You need cryptographic signing for every build: automated, keyless, and verifiable.
====

Red Hat Trusted Artifact Signer (RHTAS) provides Sigstore-based artifact signing for supply chain security. It enables developers to cryptographically sign container images and verify their provenance: ensuring that what runs in production is exactly what was built in CI.

== Why Software Supply Chain Security?

Modern software depends on hundreds of open-source libraries, base images, and third-party tools. Each of these is a potential attack surface. High-profile incidents like SolarWinds and Log4Shell demonstrated that attackers increasingly target the *build process* itself: injecting malicious code into artifacts before they ever reach production.

Software supply chain security answers a fundamental question: **"How do I know this artifact is what I think it is, and that nothing tampered with it between build and deploy?"**

== Why Sigstore / Red Hat Trusted Artifact Signer?

Traditional signing approaches (GPG keys, X.509 certificates) have well-known friction problems: keys expire, get lost, are shared unsafely, and are rarely revoked when they should be. The result is that signing is optional in practice, even when it is mandatory in policy.

**Sigstore** is an open-source project (co-founded by Red Hat, Google, and Purdue University) that makes signing effortless and verifiable by default:

* **Keyless signing**: developers sign with their OIDC identity (Keycloak, GitHub, Google). No long-lived private keys to manage or rotate.
* **Transparency log (Rekor)**: every signing event is recorded in an append-only, tamper-evident public log. You can prove when an artifact was signed and by whom.
* **Fulcio CA**: a short-lived certificate authority that issues ephemeral certificates tied to the signer's identity. Certificates expire in minutes, eliminating key sprawl.
* **Cosign**: the CLI tool that signs and verifies container images, SBOMs, attestations, and any other artifact.

**Red Hat Trusted Artifact Signer** packages all of this as an enterprise-grade, self-hosted OpenShift operator: so your signing infrastructure runs on-cluster, integrated with Keycloak for identity, without any dependency on the public Sigstore infrastructure.

== What this unlocks for your IDP

* **Every image signed at build time**: Tekton pipelines call `cosign sign` after each build. No unsigned image can enter production.
* **Verifiable provenance**: given any image digest, you can retrieve the full signing certificate chain and prove who built it, when, and from which Git commit.
* **Policy enforcement**: OPA/Gatekeeper or Kyverno policies can reject any workload whose image is not present in the Rekor transparency log.
* **SLSA compliance**: Sigstore attestations are the foundation for SLSA Level 2 and Level 3 build provenance requirements.
+
https://slsa.dev[SLSA (Supply-chain Levels for Software Artifacts)^] is an open security framework, backed by Google and the OpenSSF, that defines four levels of build integrity guarantees. Level 1 requires a build process that generates provenance; Level 2 adds tamper-resistant provenance signed by a build service; Level 3 requires a hardened, auditable build environment. Sigstore signing + Rekor attestations fulfill the cryptographic provenance requirements at Levels 2 and 3 out of the box.
* **Audit trail**: every signing event is immutable and timestamped in Rekor. Compliance and incident response teams get a complete artifact lifecycle history.

== The Helm Chart

The ArgoCD Application points to the `rhtas` chart in your GitLab repository.
Browse it here: {helm_repo_browse}/-/tree/{helm_repo_tag}/rhtas[{helm_repo_browse}/-/tree/{helm_repo_tag}/rhtas^]

The chart installs the Trusted Artifact Signer operator (via OLM) and a `SecureSign` instance that provisions the Fulcio CA, Rekor transparency log, and Cosign tooling.

== Create the ArgoCD Application

[source,bash,subs="attributes"]
----
cat <<'EOF' > trusted-artifact-signer-app.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: trusted-artifact-signer
  namespace: openshift-gitops
spec:
  project: default
  source:
    repoURL: {helm_repo}
    path: rhtas
    targetRevision: {helm_repo_tag}
    helm:
      values: |
        trusted-artifact-signer:
          instance: securesign
          email: admin@example.com
          org: my-org
          oidc: sso.{openshift_cluster_ingress_domain}/realms/sso
  destination:
    server: https://kubernetes.default.svc
    namespace: trusted-artifact-signer
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    retry:
      backoff:
        duration: 5s
        factor: 2
        maxDuration: 3m0s
      limit: 5
    syncOptions:
      - CreateNamespace=true
EOF
----

== Apply the Application

[source,bash,subs="attributes"]
----
oc apply -f trusted-artifact-signer-app.yaml
----

== Verify in the OpenShift Console

. Open the https://console-openshift-console.{openshift_cluster_ingress_domain}[OpenShift Console^]
. Navigate to *Operators → Installed Operators*
. Select the `trusted-artifact-signer` project
. Confirm **Red Hat Trusted Artifact Signer** appears with status `Succeeded`

Then explore the deployed workloads:

. Navigate to the *Topology* view in the `trusted-artifact-signer` project

== Integration with Tekton pipelines

TAS integrates with OpenShift Pipelines so that Tekton tasks can sign container images automatically. Configure your pipeline tasks to use the Sigstore signing service; signed artifacts are then verifiable for supply chain compliance.
