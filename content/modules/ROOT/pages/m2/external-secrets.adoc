== What External Secrets Operator provides

External Secrets Operator bridges external secret management systems (such as HashiCorp Vault) into Kubernetes. It:

* Syncs secrets from Vault into Kubernetes `Secret` resources
* Keeps secrets up to date when they change in the external store
* Avoids storing sensitive data in Git
* Uses `ExternalSecret` and `ClusterSecretStore` CRDs to define the sync behavior

== The Helm Chart

The ArgoCD Application points to the `external-secrets` chart in your GitLab repository.
Browse it here: {helm_repo_browse}/-/tree/{helm_repo_tag}/external-secrets[{helm_repo_browse}/-/tree/{helm_repo_tag}/external-secrets^]

The chart installs the External Secrets Operator (via OLM) and configures a `ClusterSecretStore` pointing to Vault.

== Create the ArgoCD Application

Create the ArgoCD Application YAML that deploys External Secrets Operator and its Vault integration:

[source,bash,subs="attributes"]
----
cat <<'EOF' > external-secrets-application.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: external-secrets
  namespace: openshift-gitops
  finalizers:
    - resources-finalizer.argocd.argoproj.io/foreground
spec:
  destination:
    server: https://kubernetes.default.svc
    namespace: external-secrets
  project: default
  ignoreDifferences:
    - group: admissionregistration.k8s.io
      kind: MutatingWebhookConfiguration
      jqPathExpressions:
        - '.webhooks[]?.clientConfig.caBundle'
  source:
    repoURL: {helm_repo}
    targetRevision: {helm_repo_tag}
    path: external-secrets
    helm:
      values: |
        vault-integration:
          vault:
            namespace: vault
            name: vault
            auth:
              namespace: default
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    retry:
      backoff:
        duration: 5s
        factor: 2
        maxDuration: 3m0s
      limit: 2
    syncOptions:
      - CreateNamespace=true
      - RespectIgnoreDifferences=true
EOF
----

== Apply the Application

[source,bash,subs="attributes"]
----
oc apply -f external-secrets-application.yaml
----

== Verify in ArgoCD UI

Open the ArgoCD UI and confirm the `external-secrets` application syncs successfully and shows **Healthy** status.

ArgoCD link: https://openshift-gitops-server-openshift-gitops.{openshift_cluster_ingress_domain}/applications/external-secrets[External Secrets Application in ArgoCD^]

== Verify in the OpenShift Console

. Open the https://console-openshift-console.{openshift_cluster_ingress_domain}[OpenShift Console^]
. Navigate to *Operators → Installed Operators*
. Select the `external-secrets` project from the dropdown
. Confirm **External Secrets Operator** appears with status `Succeeded`

Direct link: https://console-openshift-console.{openshift_cluster_ingress_domain}/k8s/all-namespaces/operators.coreos.com%7Ev1alpha1%7EClusterServiceVersion[Installed Operators^]

Then explore the deployed workloads:

. Navigate to the *Topology* view in the `external-secrets` project
. Verify the controller pods are `Running`

Direct link: https://console-openshift-console.{openshift_cluster_ingress_domain}/topology/ns/external-secrets?view=graph[Topology (external-secrets)^]

== Verify with CLI

[source,bash,subs="attributes"]
----
oc get pods -n external-secrets -w
----

TIP: The `-w` flag watches for changes in real-time. Press **Ctrl+C** to stop watching once all pods show `Running` and `1/1` READY.

== ClusterSecretStore and Vault

The Helm chart deploys a `ClusterSecretStore` named `vault-secret-store` that connects to the Vault instance in the `vault` namespace. This store allows `ExternalSecret` resources in any namespace to pull secrets from Vault using the configured authentication (Kubernetes auth with `rhdh-role`).
