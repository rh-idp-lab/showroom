= Deploy Red Hat Quay
:navtitle: Deploy Red Hat Quay

== What Red Hat Quay provides

Red Hat Quay is an enterprise container image registry that gives your platform a secure, private place to store and distribute container images. As part of your IDP it provides:

* A private registry for all images built by your CI/CD pipelines
* Role-based access control for image repositories
* Image vulnerability scanning via Clair
* Geo-replication and mirroring support
* Integration with Vault for credentials and with NooBaa for object storage

NOTE: Quay uses *NooBaa* (deployed as part of the foundation) as its object storage backend, and pulls its admin credentials from *Vault*. Both must be healthy before Quay finishes initialising.

== Prerequisites check

Confirm NooBaa is ready before proceeding:

[source,bash,subs="attributes"]
----
oc get noobaa -n openshift-storage
----

You should see `STATUS: Ready`.

== The Helm Chart

The ArgoCD Application points to the `quay` chart in your GitLab repository.
Browse it here: {helm_repo_browse}/-/tree/{helm_repo_tag}/quay[{helm_repo_browse}/-/tree/{helm_repo_tag}/quay^]

The chart installs both the Quay Operator (via an OLM `Subscription`) and a `QuayRegistry` instance in one shot.

TIP: 💨 **Already familiar with the GitOps pattern?** +
You deployed Pipelines in the previous section using the same create-apply-verify workflow. If you're comfortable with it, you can fast-track this deployment by skipping ahead to xref:m2/quay.adoc#_apply_the_application[Apply the Application], or continue below for the full walkthrough.

== Create the ArgoCD Application

[source,bash,subs="attributes"]
----
cat <<'EOF' > quay-application.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: quay
  namespace: openshift-gitops
  finalizers:
    - resources-finalizer.argocd.argoproj.io/foreground
spec:
  destination:
    server: https://kubernetes.default.svc
    namespace: quay-registry
  project: default
  source:
    repoURL: {helm_repo}
    targetRevision: {helm_repo_tag}
    path: quay
    helm:
      values: |
        quay-registry:
          quay:
            host: quay.{openshift_cluster_ingress_domain}
            adminUser: quayadmin
            adminUserPassword: {common_password}
          noobaa:
            name: noobaa
            namespace: openshift-storage
          vault:
            name: vault
            namespace: vault
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    retry:
      backoff:
        duration: 5s
        factor: 2
        maxDuration: 3m0s
      limit: 10
    syncOptions:
      - CreateNamespace=true
      - RespectIgnoreDifferences=true
EOF
----

== Apply the Application

[source,bash,subs="attributes"]
----
oc apply -f quay-application.yaml
----

== Verify in the OpenShift Console

. Open the https://console-openshift-console.{openshift_cluster_ingress_domain}[OpenShift Console^]
. Navigate to *Operators → Installed Operators*
. Select the `quay-registry` project from the dropdown
. Confirm **Red Hat Quay** appears with status `Succeeded`

Direct link: https://console-openshift-console.{openshift_cluster_ingress_domain}/k8s/ns/quay-registry/operators.coreos.com~v1alpha1~ClusterServiceVersion[Installed Operators (quay-registry)^]

Then explore the deployed workloads:

. Navigate to *Workloads → Pods*
. Ensure you're in the `quay-registry` project
. You should see the Quay application pods (app, Clair scanner, database, Redis) coming up progressively

Direct link: https://console-openshift-console.{openshift_cluster_ingress_domain}/k8s/ns/quay-registry/core~v1~Pod[Pods (quay-registry)^]

== Monitor the deployment

Quay takes a few minutes to initialise — the operator must first provision PostgreSQL, Redis, and then configure the registry against NooBaa object storage.

[source,bash,subs="attributes"]
----
oc get pods -n quay-registry -w
----

TIP: The `-w` flag watches for changes in real-time. Press **Ctrl+C** to stop watching once all pods show `Running` and `1/1` or `2/2` READY.

You can also track progress in the ArgoCD UI under the `quay` application. All resources should reach *Synced / Healthy* status before moving on.

ArgoCD link: https://openshift-gitops-server-openshift-gitops.{openshift_cluster_ingress_domain}/applications/quay[Quay Application in ArgoCD^]

== Verify Quay is accessible

Once the `QuayRegistry` reports `Ready`, open the Quay UI:

link:https://quay.{openshift_cluster_ingress_domain}[Quay Registry^]

Log in with:

* *Username:* `quayadmin`
* *Password:* `{common_password}`

Verify from the CLI that all pods are running:

[source,bash,subs="attributes"]
----
oc get pods -n quay-registry
----

Then check the QuayRegistry status:

[source,bash,subs="attributes"]
----
oc get quayregistry -n quay-registry -w
----

TIP: Press **Ctrl+C** once you see `REGISTRY ENDPOINT` populated and `AVAILABLE: true`.

== What was deployed

[cols="1,3",options="header"]
|===
|Resource |Purpose

|`Subscription` (quay-operator)
|Installs the Red Hat Quay Operator from OperatorHub

|`QuayRegistry` (quay-registry)
|Manages the full Quay instance: app, Clair scanner, database, Redis, object storage

|`Job` (quay-config)
|Post-install job that creates the admin user and configures the registry

|`Job` (noobaa-status)
|Waits for NooBaa to be healthy before creating the `QuayRegistry`
|===
