= Store Platform Secrets in Vault
:navtitle: Store Secrets in Vault

Several platform components share secrets: Developer Hub needs database credentials, Keycloak OIDC client secrets, and GitLab tokens. Instead of creating Kubernetes Secrets manually, we store them in Vault. The External Secrets Operator (deployed in Module 2) syncs them into the cluster.

== Write Secrets to Vault

Using the Vault pod, write the common password to the path consumed by Developer Hub and other components:

[source,bash,subs="attributes"]
----
oc exec -n vault vault-0 -- vault kv put kv/secrets/rhdh/common_password password={common_password}
----

The path `kv/secrets/rhdh/` is used by ExternalSecret resources to create Kubernetes Secrets in the `rhdh` and related namespaces.

== Verify the Secret

Confirm the secret was stored:

[source,bash,subs="attributes"]
----
oc exec -n vault vault-0 -- vault kv get kv/secrets/rhdh/common_password
----

You should see the `password` field with your lab password.

== How External Secrets Sync Works

ExternalSecret resources (deployed in Module 2) reference `ClusterSecretStore` and `kv/secrets/rhdh/*` paths. They periodically sync values from Vault into Kubernetes Secrets. When you deploy Developer Hub in Module 4, it will consume these synced secrets for Keycloak OIDC and database configuration.
