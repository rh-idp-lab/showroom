Several platform components share secrets: Developer Hub needs database credentials, Keycloak OIDC client secrets, and GitLab tokens. Instead of creating Kubernetes Secrets manually, we store them in Vault. The External Secrets Operator (deployed in Module 2) syncs them into the cluster.

== Access the Vault UI

Vault exposes a web UI via an OpenShift Route in the `vault` namespace.

Retrieve the root token from the cluster:

[source,bash,subs="attributes"]
----
oc get secret vault-token -n vault -o jsonpath='{.data.token}' | base64 -d ; echo
----

Then open the Vault UI: https://vault-vault.{openshift_cluster_ingress_domain}[https://vault-vault.{openshift_cluster_ingress_domain}^]

. Select *Token* as the authentication method
. Paste the token retrieved above
. Click *Sign in*

Once logged in, navigate to *Secrets Engines → kv → secrets → rhdh* to browse the key-value store used by the platform.

== Write Secrets to Vault

The Vault CLI inside the pod requires authentication. Export the root token first, then use it in the exec command:

[source,bash,subs="attributes"]
----
VAULT_TOKEN=$(oc get secret vault-token -n vault -o jsonpath='{.data.token}' | base64 -d)

oc exec -n vault vault-0 -- env VAULT_TOKEN=$VAULT_TOKEN \
  vault kv put kv/secrets/rhdh/common_password password={common_password}
----

The path `kv/secrets/rhdh/` is used by ExternalSecret resources to create Kubernetes Secrets in the `rhdh` and related namespaces.

== Verify the Secret

Confirm the secret was stored:

[source,bash,subs="attributes"]
----
VAULT_TOKEN=$(oc get secret vault-token -n vault -o jsonpath='{.data.token}' | base64 -d)

oc exec -n vault vault-0 -- env VAULT_TOKEN=$VAULT_TOKEN \
  vault kv get kv/secrets/rhdh/common_password
----

You should see the `password` field with your lab password.

== How External Secrets Sync Works

ExternalSecret resources (deployed in Module 2) reference `ClusterSecretStore` and `kv/secrets/rhdh/*` paths. They periodically sync values from Vault into Kubernetes Secrets. When you deploy Developer Hub in Module 4, it will consume these synced secrets for Keycloak OIDC and database configuration.
