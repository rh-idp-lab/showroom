= Explore ArgoCD (OpenShift GitOps)
:navtitle: Explore ArgoCD

ArgoCD is the GitOps engine. It watches Git repositories and keeps your cluster in sync with the desired state defined in Git.

== Open the ArgoCD UI

. Open: https://openshift-gitops-server-openshift-gitops.{openshift_cluster_ingress_domain}[ArgoCD^]
. Click **LOG IN VIA OPENSHIFT**
. Log in with `admin` / `{ocp_admin_password}`

== Navigate the ArgoCD UI

* **Applications** — lists all ArgoCD Applications (each typically deploys one Helm chart)
* **Sync status** — whether the live cluster matches Git (Synced = in sync)
* **Health status** — health of deployed resources (Healthy, Degraded, etc.)

You may see few or no Applications initially. Throughout this lab, you will create ArgoCD Applications that deploy the platform components.

== Explore via CLI

List the GitOps operator and Applications:

[source,bash,subs="attributes"]
----
oc get argocd -A
oc get applications -n openshift-gitops
----

== ArgoCD Applications

An ArgoCD Application is a Kubernetes custom resource that tells ArgoCD:

* **Source** — where to get the manifests (Git repo + Helm chart path)
* **Destination** — where to deploy (cluster + namespace)

== Anatomy of an ArgoCD Application

Example YAML structure:

[source,yaml]
----
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: my-app
  namespace: openshift-gitops
spec:
  project: default
  source:
    repoURL: {helm_repo}
    targetRevision: {helm_repo_tag}
    path: charts/my-chart
  destination:
    server: https://kubernetes.default.svc
    namespace: my-namespace
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
----

* `source.repoURL` — Git repository URL
* `source.targetRevision` — branch or tag
* `source.path` — path to Helm chart within the repo
* `destination.namespace` — target Kubernetes namespace

Throughout the lab, you will create similar Application manifests for each platform component.
