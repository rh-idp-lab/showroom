=== Step 1: OpenShift Pipelines

[source,bash,subs="attributes"]
----
cat <<'EOF' > pipelines-application.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: openshift-pipelines
  namespace: openshift-gitops
  finalizers:
    - resources-finalizer.argocd.argoproj.io/foreground
spec:
  destination:
    server: https://kubernetes.default.svc
    namespace: openshift-operators
  project: default
  source:
    repoURL: {helm_repo}
    targetRevision: {helm_repo_tag}
    path: openshift-pipelines
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    retry:
      backoff:
        duration: 30s
        factor: 2
        maxDuration: 10m
      limit: 15
    syncOptions:
      - CreateNamespace=false
      - RespectIgnoreDifferences=true
EOF
oc apply -f pipelines-application.yaml
----

Wait for `Ready=True`:

== Act 1: The Problem [3 min]

=== Talking Points

* "Every organization building on Kubernetes faces the same problem: **too many tools, too much cognitive load** for developers."
* "Developers don't want to learn Helm, ArgoCD, Vault, Tekton, Keycloak. They want to write code and ship it."
* "Platform engineering solves this by building a **self-service layer**: an Internal Developer Platform."
* "The link:https://platformengineering.org[platformengineering.org^] reference architecture defines six principles that guide successful IDP implementations. Today's demo respects all of them."
* "Today I'll show you one built entirely on **Red Hat OpenShift products**, deployed in under 2 hours using only **Helm charts and GitOps**."

=== The Six Principles

Use this table as a slide or draw it on a whiteboard. You will come back to each principle during the demo.

[cols="1,3",options="header"]
|===
|Principle |What it means for this platform

|*Product Mindset*
|The platform is a product: designed around developer needs, measured by adoption, improved continuously.

|*Golden Paths, Not Golden Cages*
|Software Templates are pre-configured workflows that make the right way the easiest way, without locking teams in.

|*Self-Service via Abstraction*
|Developers provision environments, pipelines, and secrets from a portal — no ticket, no waiting.

|*Developer Experience (DevEx)*
|Zero local setup. One login. One portal. Cognitive load minimized at every step.

|*Shared Responsibility & Governance*
|Security, signing, and secret management are embedded in the platform — not left to individual teams.

|*GitOps as the rule*
|Every infrastructure change goes through Git. ArgoCD reconciles continuously.
|===

=== Platform Architecture

|===

== Act 5: Live Deployment [5 min]

[TIP]
====
Deploy one component live to prove it takes seconds. This is the most concrete GitOps demonstration.

*Principle in action:* GitOps as the rule
====

Pick a component that isn't deployed yet (or delete one before the demo). For example, delete and redeploy `external-secrets`:

[source,bash,subs="attributes"]

[source,bash,subs="attributes"]
----
cat <<'EOF' | oc apply -f -
apiVersion: argoproj.io/v1alpha1
kind: Application

  name: external-secrets
  namespace: openshift-gitops
spec:
  project: default
  source:
    repoURL: {helm_repo}
    targetRevision: {helm_repo_tag}
    path: external-secrets

          vault:
            namespace: vault

    namespace: external-secrets-operator
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    syncOptions:
    - CreateNamespace=true

Switch to ArgoCD UI and watch it sync in real time.
