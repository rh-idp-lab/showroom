== Act 2: The Developer Experience [10 min]

[TIP]
====
Show the end result first. Start with the developer's perspective — this is the hook.
====

=== Step 1: Open Developer Hub [2 min]

Open: https://backstage-rhdh.{openshift_cluster_ingress_domain}[Developer Hub^]

* Sign in via SSO (Keycloak) — "One login for the entire platform."
* Browse the **Catalog** — "Every service, API, and component in one place."
* Show a registered component — "Docs, ownership, dependencies, all discoverable."

=== Step 2: Create an Application from a Template [3 min]

* Go to **Create** → Pick a Software Template (e.g., Quarkus Application)
* Fill in the form: name, owner, description
* Click **Create** and narrate each step:
** "A GitLab repo is being created..."
** "A Tekton pipeline is set up..."
** "An ArgoCD Application is created..."
** "The component is registered in the catalog."

=== Step 3: Follow the Pipeline [2 min]

While the template executes:

* In Developer Hub, open the newly created component
* Click on the **CI/CD** tab — show the Tekton pipeline run
* Walk through the pipeline stages: "Clone → Build → Push to Quay → Sign with Sigstore → Deploy via ArgoCD"
* "Each stage is a Tekton Task — a reusable, composable building block."

=== Step 4: Explore the Component Page [3 min]

Once the app is deployed:

* Show the **Overview** tab — "Ownership, lifecycle, system — everything in one place."
* Show the **ArgoCD plugin** — "The app is deployed and synced. Real-time status from ArgoCD."
* Show the **Tekton plugin** — "Build history, logs, success/failure — no need to leave the portal."
* Show the **Dependencies** tab (if available) — "Who depends on this service? Who does it call?"
* Click the **Dev Spaces** link — "The developer can start coding immediately in a cloud IDE."
* Open the app URL — "From template to running app in 3 minutes."

== Act 3: How It All Works — The GitOps Engine [10 min]

[TIP]
====
Switch to ArgoCD. Now peel back the curtain.
====

=== Step 1: ArgoCD Overview [2 min]

Open: https://openshift-gitops-server-openshift-gitops.{openshift_cluster_ingress_domain}[ArgoCD^]

* "Everything you just saw was deployed by ArgoCD — including ArgoCD itself."
* Show the list of Applications — "Each tile is a platform component, deployed from a Helm chart in Git."
* Click on one (e.g., `keycloak`) — Show the resource tree: "ArgoCD renders the Helm chart and reconciles every resource."

=== Step 2: Anatomy of a Deployment [2 min]

Show a terminal and display an ArgoCD Application:

[source,bash,subs="attributes"]
----
oc get application openshift-pipelines -n openshift-gitops -o yaml | head -30
----

* "This is the entire deployment definition. A source (Helm chart in Git) and a destination (namespace). That's it."
* "No `helm install`. No manual steps. Git is the source of truth."

=== Step 3: Self-Heal in Action [2 min]

Demonstrate GitOps self-healing — delete a resource and watch ArgoCD restore it:

[source,bash,subs="attributes"]
----
# Pick a non-critical pod and delete it
oc delete pod -n external-secrets -l app.kubernetes.io/name=external-secrets --wait=false
----

* Switch to ArgoCD UI — the application briefly shows **OutOfSync** then self-heals
* "I just deleted a pod. ArgoCD detected the drift and recreated it in seconds."
* "This is the power of GitOps: the cluster always converges to the state declared in Git."

=== Step 4: The Helm Chart Repository [2 min]

* "All components come from a single Helm chart repository."
* Show the repo: {helm_repo_browse}[{helm_repo_browse}^] (branch: `{helm_repo_tag}`)
* "Each folder is a component: `keycloak/`, `external-secrets/`, `redhat-developer-hub/`, etc."
* "Want to change something? Update the chart, push to Git, ArgoCD reconciles."

=== Step 5: Two ArgoCD Instances [2 min]

* "We use two ArgoCD instances: one for the **platform** (openshift-gitops), one for **developer apps** (rhdh-gitops)."
* Open: https://rhdh-gitops-server-rhdh-gitops.{openshift_cluster_ingress_domain}[RHDH GitOps^]
* "When a developer creates an app from a template, the ArgoCD Application lands here — not in the platform GitOps."
* "Separation of concerns: platform team owns platform GitOps, developers deploy through the portal."

== Act 5: Live Deployment [5 min]

[TIP]
====
Deploy one component live to prove it takes seconds.
====

Pick a component that isn't deployed yet (or delete one before the demo). For example, delete and redeploy `external-secrets`:

[source,bash,subs="attributes"]
----
oc delete application external-secrets -n openshift-gitops
----

Wait a moment, then redeploy:

[source,bash,subs="attributes"]
----
cat <<'EOF' | oc apply -f -
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: external-secrets
  namespace: openshift-gitops
spec:
  project: default
  source:
    repoURL: {helm_repo}
    targetRevision: {helm_repo_tag}
    path: external-secrets
    helm:
      values: |
        vault-integration:
          vault:
            namespace: vault
            name: vault
            auth:
              namespace: default
  destination:
    server: https://kubernetes.default.svc
    namespace: external-secrets
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    syncOptions:
    - CreateNamespace=true
EOF
----

Switch to ArgoCD UI and watch it sync in real time.

* "That's it. One YAML, applied to the cluster. ArgoCD does the rest."
* "This is how we deployed every component — in under 2 hours."

== Act 6: Code to Production — Live Cycle [8 min]

[TIP]
====
This is the "wow" moment. Show the full inner loop: code change → pipeline → signed image → deployment — all automatic.
====

=== Step 1: Open Dev Spaces [2 min]

* In Developer Hub, navigate to the component created in Act 2
* Click the **OpenShift Dev Spaces** link to open the cloud IDE

Open: https://devspaces.{openshift_cluster_ingress_domain}[Dev Spaces^]

* "This is a full VS Code IDE running inside the cluster. Zero local setup."
* Show the terminal — "Direct access to the cluster. No VPN, no port-forwarding."
* Show the Git integration — "Already authenticated to GitLab via OAuth. No SSH keys to manage."

=== Step 2: Make a Code Change [3 min]

Make a visible change to the application:

* Open a source file (e.g., `index.html`, `application.properties`, or a REST endpoint)
* Change a visible string — a title, a welcome message, a color
* Commit and push from the Dev Spaces terminal:

[source,bash]
----
git add .
git commit -m "Update welcome message"
git push
----

* "That push triggers the entire pipeline automatically."

=== Step 3: Watch the Full Cycle [3 min]

Switch between tabs to narrate the automated workflow:

. **GitLab** — "The commit landed. A webhook triggers the pipeline."
. **OpenShift Console / Developer Hub** — "Tekton is running: clone, build, push, sign, deploy."
. **Quay** — "The new image is in the registry, tagged and signed."
. **ArgoCD (rhdh-gitops)** — "ArgoCD detected the new image and is updating the deployment."
. **App URL** — Refresh the app — "There's our change. Live."

* "From code change to production in under 2 minutes."
* "The developer never left the browser. Never touched Helm, ArgoCD, or Vault."
* "**That's what an Internal Developer Platform does.**"
