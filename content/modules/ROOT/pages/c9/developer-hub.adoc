*Challenge #9: "Developers need 6 different logins. They can't find anything."*

You've built all the pieces: pipelines, registry, secrets, IDE, signing. But Golden Path Inc. developers still have to know about ArgoCD, Tekton, Quay, Vault, Dev Spaces: and log into each one separately. The CTO's vision was _one place_ for everything. Time to build that front door.
====

.Platform Engineering Principles: Product Mindset & Self-Service via Abstraction
****
Developer Hub is where the platform becomes a product. Developers do not need to understand how ArgoCD, Tekton, or Quay work: they open one portal, log in once (SSO via Keycloak), and see their services, pipelines, and templates ready to use. The platform team owns the integration — developers own the experience.
****

You have deployed all the platform services: GitOps, CI/CD pipelines, secrets management, SSO, a cloud IDE, and supply chain signing. Now it is time to tie them all together with a **developer portal**.

Red Hat Developer Hub (RHDH) is Red Hat's supported distribution of Backstage. It acts as the **single gateway** to your entire Internal Developer Platform: the one place where developers discover services, browse APIs, read documentation, and instantiate golden-path templates. It integrates with every service you have deployed so far:

* **Keycloak**: SSO authentication (Challenge #1)
* **GitLab**: source code discovery and repository creation (pre-installed)
* **ArgoCD**: application deployment status (Challenge #2/#3/#4/#5)
* **OpenShift Pipelines**: pipeline run visibility (Challenge #2/#3/#4/#5)
* **External Secrets / Vault**: secrets injection (Modules 2 & 3)
* **Dev Spaces**: one-click cloud IDE links (Challenge #6)
* **Trusted Artifact Signer**: signed artifact verification (Challenge #8)

== The Helm Chart

The chart follows the **apps-of-apps** pattern: `rhdh-bootstrap` is a lightweight ArgoCD Application that creates a second application `rhdh`, which deploys the actual RHDH workloads.
Browse it here: {helm_repo_browse}/-/tree/{helm_repo_tag}/redhat-developer-hub[{helm_repo_browse}/-/tree/{helm_repo_tag}/redhat-developer-hub^]

[cols="1,2,1,1",options="header"]
|===
|Subchart |What it deploys |Sync wave |App

|`redhat-developer-hub-prereqs`
|Kubernetes `Secrets` (GitLab token, ArgoCD password, Keycloak OAuth client, Kubernetes SA token, backend secret) and the RBAC policy `ConfigMap`
|-1
|`rhdh-bootstrap`

|`redhat-developer-hub-operator`
|OLM `Subscription` (`rhdh-operator.v1.9.1`, channel `fast-1.9`) in `openshift-operators`.
|0
|`rhdh-bootstrap`

|`redhat-developer-hub-config-template`
|Ansible job that clones the `opencodequest-templates` repo from GitLab and substitutes cluster-specific placeholders. Runs *after* the operator and Backstage CR are in place.
|3
|`rhdh-bootstrap`

|`redhat-developer-hub-application`
|A single ArgoCD `Application` resource (`rhdh`) that triggers the deployment of the instance sub-chart below.
|—
|`rhdh-bootstrap`

|`redhat-developer-hub-instance`
|`app-config-rhdh` ConfigMap, `dynamic-plugins-rhdh` ConfigMap, PVC for the dynamic plugins cache, and the `Backstage` CR managed by the operator.
|1 → 2
|`rhdh` _(child app)_
|===


== Step 1: Retrieve required credentials

[source,bash,subs="attributes"]
----
export GITLAB_TOKEN=$(oc get secret root-user-personal-token -n gitlab -o jsonpath='{.data.token}' | base64 -d)

# ArgoCD admin password (set during rhdh-gitops deployment in Challenge #5)
export ARGOCD_PASSWORD="{common_password}"

# Retrieve the Keycloak client secret for the 'backstage' client
export KEYCLOAK_TOKEN=$(curl -sk -X POST \
  "https://sso.{openshift_cluster_ingress_domain}/realms/master/protocol/openid-connect/token" \
  -d "client_id=admin-cli&username=admin&password={common_password}&grant_type=password" \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['access_token'])")

export CLIENT_UUID=$(curl -sk \
  -H "Authorization: Bearer $KEYCLOAK_TOKEN" \
  "https://sso.{openshift_cluster_ingress_domain}/admin/realms/sso/clients?clientId=backstage" \
  | python3 -c "import sys,json; print(json.load(sys.stdin)[0]['id'])")

export KEYCLOAK_CLIENT_SECRET=$(curl -sk \
  -H "Authorization: Bearer $KEYCLOAK_TOKEN" \
  "https://sso.{openshift_cluster_ingress_domain}/admin/realms/sso/clients/$CLIENT_UUID/client-secret" \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['value'])")
----

== Step 2: Create the ArgoCD Application

`rhdh-bootstrap` déploie directement les subcharts `prereqs`, `operator` et `config-template`, et crée via le subchart `application` une application fille `rhdh` qui déploie uniquement le Backstage CR (`instance`).

[source,bash,subs="specialcharacters,attributes"]
----
cat <<EOF > rhdh-bootstrap-app.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: rhdh-bootstrap
  namespace: openshift-gitops
  finalizers:
    - resources-finalizer.argocd.argoproj.io/foreground
spec:
  project: default
  source:
    repoURL: {helm_repo}
    path: redhat-developer-hub
    targetRevision: {helm_repo_tag}
    helm:
      values: |
        redhat-developer-hub-prereqs:
          namespace: rhdh
          backstage:
            argocd:
              password: $ARGOCD_PASSWORD
            gitlab:
              token: $GITLAB_TOKEN
            oauth:
              clientId: backstage
              clientSecret: $KEYCLOAK_CLIENT_SECRET

        redhat-developer-hub-config-template:
          nameOverride: "backstage"
          namespace: rhdh
          gitlab:
            host: gitlab-gitlab.{openshift_cluster_ingress_domain}
            rootPassword: {common_password}
          cluster:
            subdomain: {openshift_cluster_ingress_domain}
          backstage:
            host: backstage-rhdh.{openshift_cluster_ingress_domain}
          keycloak:
            host: sso.{openshift_cluster_ingress_domain}
            realm: sso
            clientId: backstage
            clientSecret: $KEYCLOAK_CLIENT_SECRET
          gitops:
            host: rhdh-gitops-server-rhdh-gitops.{openshift_cluster_ingress_domain}
          quay:
            project: quayadmin

        redhat-developer-hub-application:
          helm:
            inlineValues:
              namespace: rhdh
              backstage:
                host: backstage-rhdh.{openshift_cluster_ingress_domain}
              cluster:
                subdomain: {openshift_cluster_ingress_domain}
              gitlab:
                host: gitlab-gitlab.{openshift_cluster_ingress_domain}
              keycloak:
                host: sso.{openshift_cluster_ingress_domain}
                realm: sso
              gitops:
                host: rhdh-gitops-server-rhdh-gitops.{openshift_cluster_ingress_domain}
              quay:
                project: quayadmin
  destination:
    server: https://kubernetes.default.svc
    namespace: openshift-gitops
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    syncOptions:
      - CreateNamespace=true
    retry:
      limit: 10
      backoff:
        duration: 30s
        factor: 2
        maxDuration: 5m
  ignoreDifferences:
    - group: rhdh.redhat.com
      kind: Backstage
      jsonPointers:
        - /metadata/annotations/rhdh.redhat.com~1ext-config-hash
        - /spec/monitoring
        - /status
    - group: apps
      kind: Deployment
      name: backstage-developer-hub
      jsonPointers:
        - /spec/strategy
        - /spec/template/metadata/annotations/rhdh.redhat.com~1ext-config-hash
EOF
----

Apply it:

[source,bash]
----
oc apply -f rhdh-bootstrap-app.yaml
----

== Verify

=== Verify in ArgoCD UI

Open the ArgoCD UI and confirm **two** applications are present and sync successfully:

* `rhdh-bootstrap` → **Healthy** (deploys the `rhdh-application` sub-chart)
* `rhdh` → **Healthy** (deploys all RHDH workloads)

ArgoCD link: https://openshift-gitops-server-openshift-gitops.{openshift_cluster_ingress_domain}/applications[ArgoCD Applications^]

=== Verify in the OpenShift Console

. Open the https://console-openshift-console.{openshift_cluster_ingress_domain}[OpenShift Console^]
. Navigate to the *Topology* view in the `rhdh` project
. Verify all Developer Hub pods are `Running`

Direct link: https://console-openshift-console.{openshift_cluster_ingress_domain}/topology/ns/rhdh?view=graph[Topology (rhdh)^]

=== Verify with CLI

[source,bash,subs="attributes"]
----
oc get pods -n rhdh -w
----

TIP: The `-w` flag watches for changes in real-time. Press **Ctrl+C** to stop watching once all pods report `Running` and `1/1` or `2/2` READY.

[NOTE]
====
*First startup takes a few minutes.* Developer Hub installs its dynamic plugins on the first boot, which requires downloading and initializing each plugin before the interface becomes available. A PVC persists the plugin cache — subsequent restarts skip the downloads and are significantly faster.
====
