.Platform Engineering Principle: Self-Service via Abstraction
****
This is the ultimate proof of concept. A developer opens a browser IDE, edits a file, pushes a commit — and the platform handles everything else: build, sign, push, deploy. No ticket, no runbook, no platform team involvement.
****

== Open Dev Spaces from the component

. In Developer Hub, open the `hero` component you created in the previous step.
. On the **Overview** tab, click **Open in Dev Spaces** in the shortcut links.

Dev Spaces opens a browser-based VS Code IDE already cloned and authenticated to GitLab — no local setup, no SSH keys.

[NOTE]
====
Dev Spaces may prompt you to re-authenticate with GitLab before cloning the repository. If a login screen appears, use your lab credentials:

* *Username*: `user1`
* *Password*: `{common_password}`
====

== Make a change and push

. Open any source file (for example, a REST endpoint or a string constant).
. Make a small visible change: a label, a message, a comment.
. In the **Source Control** panel (left sidebar), stage the change, write a commit message, and click **Sync** to push.

The push triggers the Tekton pipeline automatically via a GitLab webhook.

== Watch the pipeline run

Switch back to Developer Hub and open the **CI/CD** tab on the `hero` component. The pipeline stages appear in sequence:

. **Clone** — source code fetched from GitLab
. **Build** — Maven compiles and runs tests
. **Push** — image pushed to Quay (`quayadmin/user1-hero`)
. **Sign** — image signed by Trusted Artifact Signer (if enabled)
. **Deploy** — ArgoCD detects the new image tag and updates the deployment in `workshop-dev`

[WARNING]
====
The demo environment has limited cluster resources (CPU, memory, ephemeral storage). The first pipeline run — which downloads all Maven dependencies and builds the container image — may fail with resource pressure errors such as `node(s) had untolerated taint {node.kubernetes.io/disk-pressure}` or `OOMKilled`.

If the pipeline fails, retry the run from the **CI/CD** tab. Subsequent runs are faster because Maven artifacts are cached.
====

== Verify the deployment

Once the pipeline completes:

* **CI/CD tab**: all stages green, image tag updated
* **ArgoCD tab**: application synced and healthy
* **Topology tab**: pods restarted with the new image
* **Image tab**: new image visible in Quay with vulnerability scan results

From commit to running update: the developer never opened a terminal, never touched a Helm chart, never contacted the platform team.
