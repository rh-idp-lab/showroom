== Configuration as Code

The entire Developer Hub configuration is managed as code in the platform Helm chart:

https://gitlab-gitlab.{openshift_cluster_ingress_domain}/idp-lab/helm/-/tree/main/redhat-developer-hub[Developer Hub Helm Chart^]

The `redhat-developer-hub-instance` sub-chart contains the ConfigMaps that configure the Red Hat Developer Hub operator. This follows the **Infrastructure as Code** approach: every change to the portal is version-controlled, reviewed, and deployed via ArgoCD. No manual configuration in the UI.

Browse the chart to see:

* **RHDH configuration**: Authentication (Keycloak OpenID Connect (OIDC)), integrations (GitLab, ArgoCD), base URL, and theme
* **Plugin configuration**: Which dynamic plugins are enabled (Tekton, ArgoCD, Kubernetes, Keycloak, Quay, etc.) and their settings
* **Catalog configuration**: Catalog locations, rules, and providers that define where Developer Hub discovers components, APIs, users, groups, and templates

== Explore the Catalog

The Catalog is the heart of Developer Hub. Navigate to **Catalog** in the left menu.

=== Users & Groups

. Click on **Kind** filter and select **User**
. You should see the users synced from Keycloak: "These are your platform users, imported automatically from the SSO realm."
. Switch to **Group**: "Teams and roles from Keycloak map to ownership in Developer Hub."

This sync is handled by the **Keycloak Org Entity Provider** plugin. Every user and group in the `sso` realm is automatically reflected in the catalog.

=== Domain & System

The catalog organizes software entities into a two-level hierarchy that mirrors your organizational structure.

A **Domain** groups related systems under a business area. A **System** groups related components and APIs into a coherent product or service boundary. Components created by developers will declare which System they belong to.

For this lab, one Domain and one System are pre-registered from the https://gitlab-gitlab.{openshift_cluster_ingress_domain}/rhdh/opencodequest-templates/-/blob/main/entities.yaml[entities.yaml^] file:

[cols="1,1,3",options="header"]
|===
|Kind |Name |Description

|Domain
|`opencodequest`
|Top-level business domain grouping all OpenCodeQuest workshop assets

|System
|`opencodequest`
|The workshop system: components you create in the templates will reference this system
|===

. Switch the **Kind** filter to **Domain**: you should see `opencodequest`
. Switch to **System**: you should see `opencodequest` linked to the domain above
. When creating a new component with a Software Template, select `opencodequest` in the *System* field to attach your service to this shared context

== Plugin ecosystem

The installed plugins are directly visible in the catalog:

. In the left menu, click **Catalog**
. Open the **Kind** filter and select **Plugin**

Each entry describes a dynamic plugin installed in this Developer Hub instance. The data-bearing plugins (Tekton, ArgoCD, Quay, Kubernetes) will surface live information on component pages once the first component is deployed in Challenge #10.

TIP: The list of enabled plugins and their configuration is in the https://gitlab-gitlab.{openshift_cluster_ingress_domain}/idp-lab/helm/-/tree/main/redhat-developer-hub/redhat-developer-hub-instance[Developer Hub instance chart^]. To add or change a plugin, update the chart and push to Git: ArgoCD handles the rest.
