== Welcome!

In this hands-on lab, you will build a fully functional **Internal Developer Platform (IDP)** on Red Hat OpenShift — step by step, using only **Helm charts** and **GitOps**.

By the end of this 2-hour session, you will have assembled a platform that enables developers to self-service their way from idea to production, with built-in security, observability, and golden paths.

=== What is an Internal Developer Platform?

An Internal Developer Platform is a self-service layer built on top of your infrastructure that reduces cognitive load for developers. It provides:

* **A developer portal** — a single pane of glass to discover services, APIs, and documentation
* **Golden paths** — opinionated, pre-built templates that encode best practices
* **Automated CI/CD** — pipelines triggered from code to production
* **Secrets management** — secure, automated secret injection
* **Identity and access control** — SSO across all platform services

=== Prerequisites

* An OpenShift 4.20+ cluster (provided)
* A web browser (Chrome/Firefox recommended)
* Basic knowledge of Kubernetes, YAML, and Helm

NOTE: No local CLI installation required. All commands run directly from the in-browser terminal on the right side of this page.

=== How This Lab Works

Every component is deployed using the **GitOps pattern**:

. You create an ArgoCD `Application` resource that points to a Helm chart
. ArgoCD reconciles the desired state from Git into your cluster
. You verify the deployment in the OpenShift Console and ArgoCD UI

All Helm charts are sourced from your GitLab instance: {helm_repo_browse}[{helm_repo_browse}^] (branch: `{helm_repo_tag}`)

TIP: Use the **Terminal** tab on the right to run `oc` and `helm` commands. Use the other tabs to open the OCP Console, ArgoCD, GitLab, and Developer Hub directly in your browser.
